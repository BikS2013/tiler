01 · Scope
Tile one desktop. Touch nothing else.

Tiler does HyprMac's core job — Hyprland-style BSP “dwindle” tiling with keyboard focus, swap and resize — but only on the desktops the user turns on, one at a time.

A desktop is one Space on one display. Space ids change at login; the Space uuid does not, so that is the key that persists.

// Desktop.swift
struct DesktopKey: Codable, Hashable {
    let displayUUID: String
    let spaceUUID: String
}

The hard rules

  • Never touch a window outside a tiled desktop's display and Space — except the focused, untiled window when the user asks for the move/resize mode.
  • No polling, no active event tap: react to AX and NSWorkspace events. Focus follows mouse uses a listen-only mouse tap, only while it is on.
  • Every AX call for an app runs on that app's own thread.
  • Act on moved/resized notifications only while the mouse is down.
  • Every config key is required; no silent defaults.

02 · Threads
The main thread decides. App threads talk to apps.

Main thread

Controller, menu, Settings, overlay, Carbon hotkey events, NSWorkspace notifications. Owns all state; never makes an AX call.

One RunLoopThread per app

AXObserver source, window reads and writes. A hung app stalls only its own thread — and at most 1 s per call.

Nothing tiled, nothing running

Handles exist only while a desktop is tiled. Turning the last one off took the process from 20 threads to 8.

// AppHandle.swift — work hops to the app's thread
func perform(_ block: @escaping () -> Void) {
    guard let runLoop else { return }
    CFRunLoopPerformBlock(runLoop,
        CFRunLoopMode.defaultMode.rawValue, block)
    CFRunLoopWakeUp(runLoop)
}

// results come back on main
func resolve(_ ids: Set<CGWindowID>,
             completion: @escaping (Facts) -> Void) {
    thread.perform { [self] in
        refreshElements()
        let facts = ... isTileable(el) ...
        DispatchQueue.main.async { completion(facts) }
    }
}

02 · Desktop identity
Which Space is showing, and which windows are on it.
SkyLight callUsed for
CGSCopyManagedDisplaySpacesEvery Space with id, uuid and type; desktop numbers. Run at launch, on toggle and when Spaces change (~1–15 ms).
SLSManagedDisplayGetCurrentSpaceThe Space a display shows now. Tens of µs, so never cached.
SLSCopySpacesForWindowsThe Spaces a window belongs to (mask 0x7).
SLSManagedDisplayIsAnimatingSkip reconcile mid-switch, when the list mixes two desktops.
// Spaces.swift
static func current(onDisplay uuid: String)
        -> SpaceID {
    let id = SLSManagedDisplayGetCurrentSpace(
        connection, uuid as CFString)
    // "Displays have separate Spaces" off:
    // every display shows the "Main" Space
    return id != 0 ? id
        : SLSManagedDisplayGetCurrentSpace(
            connection, "Main" as CFString)
}

A desktop is visible when its display's current Space equals its stored Space id. Ids are re-resolved from the uuid at launch and on display changes; a desktop deleted in Mission Control is forgotten.

desktops.json keeps floating windows as id + owner pid + frame (read 0.3 s after a move, saved ≤ 1/s). A restore keeps an id only if that pid still owns it, then puts the frame back once the desktop is on screen. Re-floating reuses the last frame if ≥ 50 % is on the display.

03 · Event flow
From a notification to a written frame.
Created windows trigger extra passes at +0.15 s and +0.5 s (some apps show the window late); a window moved by a script gets one at +0.4 s (its Space updates late); an untileable window is re-checked once after 0.6 s.

03 · Reconcile
Six steps, about a millisecond.
1
Skip unless a tiled desktop is visible; wait while its display is animating a Space switch.
2
One CGWindowListCopyWindowInfo(onScreenOnly); keep layer-0 windows of other apps with alpha > 0.
3
Per visible desktop: centre on its display and its Space in SLSCopySpacesForWindows.
4
Re-check the Space did not change during the read; if it did, the next event redoes it.
5
Remove vanished and always-float windows; insert new tileable ones next to the last focused tile.
6
Lay out only if something changed, and write only frames that differ from the last one written.

When is a window tileable?

  • role AXWindow, subrole AXStandardWindow
  • not minimised, not full screen
  • an enabled green button (dialogs and settings panes have none)
  • AXSize is settable
  • app not in floatingApps

Everything else floats and is never moved.

03 · Writing frames
Write the newest frame only, in an order apps accept.
  • Coalesced. setFrame stores the newest frame per window and schedules one flush. A slow app (iTerm2 took up to 700 ms) never replays stale layouts.
  • Size → position → size. The first resize cannot clamp the move at a screen edge; the second fixes a resize clamped by the old position.
  • AXEnhancedUserInterface is switched off for the writes, or the app animates every resize.
  • Bounded. AXUIElementSetMessagingTimeout = 1 s, system-wide and per element.
// AppHandle.swift — on the app's thread
private func flushFrames() {
    lock.lock()
    let frames = pendingFrames
    pendingFrames.removeAll()
    flushScheduled = false
    lock.unlock()
    let enhanced = bool(app,
        "AXEnhancedUserInterface") == true
    if enhanced { set(app, ..., false) }
    defer { if enhanced { set(app, ..., true) } }
    for (id, frame) in frames {
        guard let el = elements[id] else { continue }
        setSize(el, frame.size)
        setPosition(el, frame.origin)
        setSize(el, frame.size)
    }
}

03 · Feedback-loop rule
React to window moves only while the mouse button is down.

Tiler's own writes produce moved/resized notifications too. So do apps that refuse a size or snap themselves. Acting on those would start a fight.

The rule: with no mouse button down, a move of a tiled window is ignored. With the button down it is a user drag, handled once on release.

03 · Layout
A binary space partition, dwindle style.

A new window splits the last focused tile along its longer side and takes the second half. Ratios are clamped to 0.1–0.9; frames are rounded to whole points so neighbours never overlap.

OperationWhat it does
insert / removeSplit a leaf; on removal the sibling takes the parent's place.
swapExchange two leaves' windows.
moveDividerPrefer the divider on the arrow's side, else the opposite one.
adoptResizeTurn dragged edges into ratios of the splits behind them.
toggleOrientationSide by side ↔ stacked for one split.
mirror · equalizeFlip left ↔ right; set every ratio to 0.5.

03 · Neighbours
Which window is “to the left”?

Focus and swap move by geometry, not by tree position, so the keys do what the eye expects. Geometry.neighbor ranks every frame on the arrow's side (4 pt tolerance):

1
overlaps the source across the movement axis
2
then the smaller gap between the facing edges
3
then the smaller offset between centres
4
then the lower window id, so ties are stable

04 · Focus on macOS 14+
Focusing another app's window from the background.

Since macOS 14, NSRunningApplication.activate() from an inactive app is ignored (“cooperative activation”). The first focus hotkeys did nothing.

Tiler uses what yabai and AeroSpace use: bring the process forward with the target window, post a synthetic make-key-window record, then AXRaise.

Which display is “active”?

The display of the focused window, else the one under the mouse. SLSCopyActiveMenuBarDisplayIdentifier reported the wrong display on macOS 27 and swallowed keys.

// PrivateAPI.swift
func focusWindow(pid: pid_t, wid: CGWindowID) {
    var psn = ProcessSerialNumber()
    guard GetProcessForPID(pid, &psn) == noErr
        else { return }
    _ = _SLPSSetFrontProcessWithOptions(
            &psn, wid, 0x200) // user generated
    // make-key-window record (layout: yabai)
    var bytes = [UInt8](repeating: 0, count: 0xf8)
    bytes[0x04] = 0xf8; bytes[0x3a] = 0x10
    // wid at 0x3c, 0xff over 0x20..<0x30
    bytes[0x08] = 0x01
    _ = SLPSPostEventRecordTo(&psn, &bytes)
    bytes[0x08] = 0x02
    _ = SLPSPostEventRecordTo(&psn, &bytes)
}

04 · Move/resize mode
Keyboard moves for untiled windows, borrowed keys.
  • Scope. ⌃⌘M acts on the focused window only, and only when no tiled desktop holds it (isTiled). A tiled window gets a note instead.
  • Keys exist only in the mode. Arrows, ⇧/⌥ arrows, C, M, Return, Esc are borrowed Carbon hotkeys; pressed/released events drive a repeat timer (0.3 s, then 45 ms). App switch, Space change or a click ends it.
  • Own AX thread. WindowMover reads the focused window and writes frames on a RunLoopThread; only the newest frame is written (size → position → size), then the frame the app accepted is read back.
  • Pure arithmetic. WindowNudge in TilerCore: 40 pt or 8 pt steps, top-left anchored resize, min 160×100, clamped to the usable area minus the outer gap.

04 · Configuration
One file, strictly parsed, written back by Settings.
  • ~/Library/Application Support/Tiler/config.json, written from a template on first launch.
  • Every key required. Missing, unknown, out-of-range or duplicate keys are errors, never defaults. The last good config stays in force; the menu and Settings show the error.
  • Config.json() writes every key in a fixed order. 0.4 added focusFollowsMouse (bool) and focusDelay (0.05–1 s).
  • While the file has an error, Settings is read-only: it never overwrites a file being fixed by hand.
  • Upgrades. A new setting is a missing key, so an error. Settings offers Add Missing Settings: Config.addingMissingSettings adds only the missing keys from the template, by explicit click.

05 · Known limits
Still open.

Minimum sizes

Apps that refuse a width overlap their neighbour (Outlook stops at 770 pt). A fix must read back sizes without oscillating.

Shared shortcuts

Carbon accepts a combination another tool already owns, and that tool wins. Settings can only see clashes inside Tiler.

Other window tools

Rectangle, Hammerspoon or HyprMac on the same desktop act on the same windows. Use one manager per desktop.

Drag-resize

Unit-tested through adoptResize; drag-swap was checked live, drag-resize not yet.

Tahoe corners

Large, varying window corner radii on macOS 26+ make equal gaps look uneven. Cosmetic.

Shared Spaces

“Displays have separate Spaces” off is handled (the “Main” Space) but not checked live.
